# 구현 계획

## 기획 요약

- 문서 수는 충분히 많다고 가정. 계속 추가되지만 실시간일 필요는 없음 → **새벽 배치로 처음부터 재구성**해도 됨.
- 문서는 영어 포함, 질문은 주로 한국어 → **다국어 임베딩 모델**.
- "에러코드 A101" 같은 질문에서 의미 검색만 쓰면 A102 등 비슷한 문서가 먼저 나옴 → **하이브리드 검색**(키워드 + 의미) 필수.
- 처음엔 2GB AWS 서버, 이후 8GB 갤럭시폰 홈서버로 이전.

## 전체 구조

```
[새벽 배치 · cron]
 수집기 → 정제 → 청킹 → 식별자 추출 → 임베딩(캐시) → index_new.db → index.db 원자적 교체

[요청]
 브라우저 → Caddy(HTTPS, basic_auth) → FastAPI(127.0.0.1:8000)
   ├ /search : 하이브리드 검색 결과 (디버그·평가용)
   └ /ask    : 검색 → LLM → 한국어 답변 + 출처
```

API 프로세스(상시)와 배치 프로세스(새벽에만)는 분리한다.

## 데이터 설계

| 저장소 | 테이블 | 내용 |
| --- | --- | --- |
| index.db | `documents` | 문서 id, 제목, 회사, 발생일, 원문 URL, 언어 |
| | `chunks` | 청크 id, 문서 id, 섹션명, 본문 |
| | `chunks_fts` (FTS5) | BM25용. `unicode61` + `tokenchars '-_'` (ORA-00600이 안 쪼개지게) |
| | `chunks_vec` (sqlite-vec) | 384차원 벡터 |
| | `doc_codes` | 추출한 식별자, 청크 id |
| cache.db | `embeddings` | (청크 텍스트 해시, 모델명) → 벡터 |

캐시 키에 모델명을 넣어서, 모델을 바꾸면(폰에서 bge-m3 등) 자동으로 새로 계산되게 한다.

## 단계

- [x] **1단계. 프로젝트 기반과 /health**
  - 완료 기준: 인증 없이 `/health` → 401, 인증하면 `{"status":"ok"}`
- [ ] **2단계. 수집기**
  - 출처: 공개 포스트모템 모음(예: GitHub danluu/post-mortems)의 링크 목록부터. (출처 최종 확정 필요)
  - 원문 HTML을 `data/raw/`에 저장, 수집 상태 기록(URL, 받은 날짜, 성공/실패, 사유)
  - 이미 받은 문서는 다시 받지 않음, 요청 간 간격, robots.txt 준수, 깨진 링크는 실패로 기록
  - 본문 텍스트만 추출 (trafilatura 등)
  - 완료 기준: 문서 수십 개가 정제 텍스트로 저장되고 수집 성공률이 확인됨
- [ ] **3단계. 인덱서 배치**
  - 청킹: 제목(heading) 기준 섹션 분할, 긴 섹션은 300~400 토큰 + 약간 겹침. 청크 앞에 "문서 제목 + 섹션명"
  - 식별자 추출: 정규식(A101, ORA-00600, HTTP 503, CVE-…, OOMKilled 등). 패턴은 설정 파일로
  - 임베딩: e5-small ONNX, 캐시에 없는 청크만 계산, 작은 배치로 처리
  - 적재 후 검증(청크 수 > 0 등) 통과 시 `os.replace`로 교체
  - 완료 기준: 전체 재구성 성공, 두 번째 실행은 임베딩 대부분 건너뜀
- [ ] **4단계. 하이브리드 검색 /search**
  - 식별자 추출 → BM25 top50 + 벡터 top50 → RRF(k=60) → 식별자 일치 가산점 → 문서당 최대 2청크
  - 디버그 모드: BM25 순위, 벡터 순위, 가산점 여부 표시
  - 완료 기준: "A101 장애"류 질문에서 해당 문서가 1~3위
- [ ] **5단계. 평가셋**
  - 한국어 질문 약 30개 + 정답 문서 (식별자형 / 의미형 / 혼합형)
  - 벡터만 / BM25만 / 하이브리드를 recall@5, MRR로 비교하는 스크립트
  - 완료 기준: 하이브리드 우위가 숫자로 확인됨. 이후 튜닝은 이 숫자 기준
- [ ] **6단계. RAG 답변 /ask**
  - 상위 6~8청크 + 메타데이터 → LLM. "근거로만, 한국어로, 출처 번호 표시, 없으면 모른다고"
  - 응답 시간·토큰 로그, 하루 호출 상한
- [ ] **7단계. 웹 UI** — 정적 HTML 한 장: 질문창, 답변, 출처 카드, "검색 결과만 보기" 토글
- [ ] **8단계. 운영 자동화** — cron 새벽 배치(예: 03:30), 실패 시 기존 index.db 유지, raw/·cache.db 백업
- [ ] **9단계. 개선** — 질문을 영어 키워드로 바꿔 BM25에 추가, 리랭커(API), 메타데이터 필터

## 2GB 서버 주의

- 메모리 예산: OS+Caddy ~350MB, API ~100MB, e5-small ONNX ~200–300MB, 배치는 별도 프로세스
- swap 2GB 설정됨. 배치는 `nice`로 낮은 우선순위
- sqlite-vec는 brute-force. 수십만 청크 넘으면 지연 측정 후 int8 양자화 검토. 검색은 인터페이스로 분리해 교체 가능하게

## 미정 사항

1. LLM API 제공자와 키 (6단계 전까지)
2. 데이터 출처 확정 (2단계 시작 시)
3. 공개 범위: 혼자 쓰면 basic_auth로 충분, 공유하면 재검토
